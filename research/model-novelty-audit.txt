Fixed-program family: model correspondence and literature audit
Date: 2026-10-16
Formalization reviewed: commit d94b677, branch nondeterministic-prefix
Follow-up: specialized small-step machine added after commit 45d7058.

RESULT UNDER REVIEW

For each integer p >= 1, one finite first-order nondeterministic recursive
program over (N, rem, eq0), with generator arity W = 4^p + 5, computes gcd
and has limsup_a max_{1<=b<=a} c_P(a,b)/log_2(a) <= 3/p. Here c_P is the
minimum remainder-call count of a convergent computation. Equivalently, for
every epsilon > 0 there are a fixed program P and a constant B such that
c_P(a,b) <= epsilon log_2(a) + B for all a >= b >= 1.

Conclusion: no model mismatch found. The theorem can be included in the main
paper. The operational correspondence below is now kernel-checked for the
specialized two-stack machine in RegisterSmallStep. No matching uniform
small-coefficient result was located in the
sources checked. This is a bounded literature search, not a proof of novelty.

MODEL AUDIT

Primary reference: Yiannis N. Moschovakis, Abstract Recursion and Intrinsic
Complexity, Lecture Notes in Logic 48, 2019. Page numbers are printed pages.
https://www.math.ucla.edu/~ynm/lectures/aricplace/c-aric.pdf

1. Syntax and finite choice (Section 2A, pp. 49-50; Section 2E, pp. 82-83).
   In ShortGCD/RegisterSyntax.lean, Fn has four constructors. Their arities
   are W, W, 3, 1; every function has a finite set of bodies. Expr contains
   variables, remainder, a zero-test conditional, and calls. Each body uses
   only its formal parameters. For fixed W these are finite first-order
   equations. The Fin indices and Function.update in the Lean definitions
   construct syntax; they are not primitive operations on runtime values.
   iteZero desugars to a conditional with the primitive eq0 as its guard.
   The semantic occurrences of 0 do not supply a numeric-constant instruction.

2. Partial remainder (Section 1A, (1A-2), p. 8).
   Eval.rem requires a positive divisor. Nat.mod's total value at divisor
   zero is therefore never used as a successful primitive call. A branch
   attempting a zero divisor has no convergent evaluation.

3. Convergence and correctness ((2E-2), p. 82).
   Syntax.eval_head_correct covers every terminating evaluation, and
   Syntax.eval_head_exists supplies one on every natural input for W >= 2.
   Incorrect candidates enter loop; Syntax.Eval.loop_free excludes finite
   evaluations of loop. Divergent and stuck branches do not affect the
   successful-computation cost. No fairness or all-branches termination is
   assumed. The zero-input head branch returns a when b = 0, including (0,0).

4. Cost ((2E-5), p. 84).
   Use the selected primitive set {rem}. Each successful remainder node
   costs one; internal calls and eq0 calls cost zero in this norm. Arguments
   are evaluated separately and their costs are added, even if expressions
   are syntactically identical. The verification wrapper adds exactly two
   remainder calls when b > 0. The theorem is not a bound on total machine
   steps or on deterministic search for a successful computation.

5. Argument order and calling contexts (Table 1, p. 75; Lemma 2D.1, p. 76).
   The book's composition rule evaluates arguments right to left. Lean Eval
   records a finite tree for every argument, its value, and its cost, without
   an explicit order. For these pure terms, the following correspondence
   preserves results and remainder counts in both directions.

   Forward: induct on a finite Eval tree after substituting its parameter
   values. For a call, execute the argument trees from right to left, use
   the internal transition for the chosen body, and execute its tree.
   Transition locality embeds each argument computation in the unchanged
   surrounding context. For rem, execute the right and left trees, then
   one external remainder call. For a conditional, execute its guard, one
   eq0 call, and the chosen branch. Variables require no remainder call.

   Reverse: decompose a finite convergent machine computation at its
   completed arguments and selected body or conditional branch. Induct on
   the lengths of these proper subcomputations to obtain their Eval trees.
   The composition and call transitions give exactly the additive costs
   in Eval. An undefined remainder or an infinite loop cannot appear in a
   convergent decomposition.

   Each call occurrence makes its own nondeterministic choice. There is no
   shared mutable state or global restriction on choices, so serialization
   changes neither their availability nor their results. This argument uses
   the transition rules directly; the deterministic implementation theorem
   2D.2 alone would not establish nondeterministic cost preservation.

   Follow-up formalization: Syntax.Machine.eval_iff_steps proves the exact-cost
   equivalence, and Step.context proves transition locality. The machine has
   an explicit control stack (top at head) and a tagged natural/boolean value
   stack. compZero pushes a zero-test term and pending branch; compTest
   expands that term; eq0 makes the external test; branchTrue/branchFalse
   select the continuation. Thus testing and branching are separate steps.
   The call transition chooses a body from the same finite set as Eval.
   Closures represent substitution; their environments are not data values
   available to program instructions. Only the rem transition has cost one.
   This is a specialization of the transition table, not a formalization of
   the book's theory for arbitrary structures, vocabularies, and programs.

6. Nested calls and storage.
   The caller's other actual values remain in its context while one nested
   generator call returns a value. The caller can therefore retain v while
   a child computes gcd(m,u). A child can use only its own parameters, not
   arbitrarily read older frames. W bounds generator arity, not the entire
   recursive stack or total memory. Positive scaling preserves selected
   successful runs and costs (RegisterProgram.Run.scale).

7. Two syntactic presentations.
   Lean inlines setters. The Python compiler (and an expanded research note,
   since removed from the repository) use
   set_i(x,z) = gen(x[i <- z]), of arity W+1. These setters have one body and
   add no external calls. Call-by-value evaluates z once before the setter
   body; after inlining, it is evaluated once in its generator argument
   position. All other arguments are variables. Thus inlining preserves
   results and remainder counts, although it changes internal-call counts.
   This equivalence is not a separate Lean theorem about the Python AST.

8. What the kernel checks and what it does not.
   RegisterProgram -> RegisterMachine -> RegisterPrefix -> RegisterCost ->
   RegisterRecurrence -> RegisterAsymptotic -> RegisterSyntax ->
   RegisterSmallStep checks the
   operational recurrence, asymptotic bound, translation into finite syntax,
   and correctness and existence for syntactic evaluations. In particular,
   Syntax.arbitrarily_small_program fixes p before quantifying over inputs.
   Syntax.run_invokes is an exact-cost forward translation; correctness of
   arbitrary syntactic evaluations is proved independently. No reverse
   translation to the register relation is needed for the upper bound.
   Exact-cost correspondence with the specialized machine is now checked.
   Syntax.Machine.head_correct, head_exists, eventually_steps_bound, and
   arbitrarily_small_program transfer the results to transition sequences.
   The Python interpreter and its setter-inlining equivalence are not
   formalized in Lean. The axiom audits report only propext, Classical.choice,
   and Quot.sound.

LITERATURE SEARCH AND LIMITS

The book's Sections 2E and 6C are the closest direct comparison. Pratt's
program is presented in Theorem 2E.2 (pp. 85-86), with the Fibonacci bound
discussed again in Corollary 6C.7 (p. 188). This supplies a special-input
comparison, not the all-input small-coefficient theorem under review. The
book identifies Pratt's 2008 source as an unpublished manuscript titled
"Euclidean gcd is exponentially suboptimal: why gcd is hard to analyse".
That manuscript was not obtained; no claim is made about its full contents.

Web searches included combinations of "Moschovakis", "nondeterministic",
"gcd", "remainder", "Pratt", "nuclid", "speedup", "speed-up", and
"arbitrarily small", as well as the exact title of Pratt's manuscript.
No matching theorem was located. Search results about bit complexity, batch
gcd, or RAM algorithms with additional primitives were not treated as results
in this model. Bshouty's different RAM result remains cited separately in
the main paper.

Ordinary macro expansion or unrolling does not by itself give this result:
in the selected external-call norm, each occurrence of rem still costs one.
A speedup theorem for another machine model cannot be transferred just by
renaming its time unit. This observation does not rule out an unlocated
general theorem with stronger applicability; it explains why generic
machine-time speedup is not a sufficient novelty objection on its own.

No assertion of "first", exhaustive coverage, or confirmed priority should
be based on this search. No experts were contacted. A useful next external
check is to ask the relevant authors whether Pratt's unpublished manuscript
or later work contains a uniform all-input coefficient improvement.

PUBLICATION CONSEQUENCE

Include the theorem as a second result, with its complete fixed-prefix proof
and the explicit finite program. Keep the main headline about the failure of
logarithmic uniform-process lower bounds. The program-family theorem leaves
the Main Conjecture intact: its lower-bound coefficient may depend on the
program. Choosing W as a function of input size would change the program
and does not yield a single sublogarithmic algorithm.
