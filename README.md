# The Euclidean algorithm is not optimal among uniform processes

Euclid's algorithm computes gcd(a, b) with about 1.44 log₂ a remainder operations in the
worst case. Van den Dries and Moschovakis asked whether any algorithm restricted to the
remainder operation and a zero test can do essentially better. Moschovakis's *Main
Conjecture* says no: for every such algorithm α there is an r > 0 such that

$$\mathrm{calls}_{\mathrm{rem}}(\alpha, a, b) > r \log a \quad \text{for infinitely many pairs } a > b \ge 1.$$

Lower bounds like this are normally proved for Moschovakis's *uniform processes*, an
abstract model of any computation that learns about its inputs only through the given
operations; every program gives one. Moschovakis conjectured that the logarithmic lower
bound already holds there: Conjecture 3.4 of his 2012 notes, and the precise version
(4F-5) of the Main Conjecture in his 2019 book.

**Main result: those uniform-process conjectures are false.** Every pair a ≥ b ≥ 1 has a
derivation of gcd(a, b) with

$$\bigl(3 + o(1)\bigr) \frac{\log_2 a}{\log_2 \log_2 a}$$

remainder calls, where each call takes the remainder of two values already computed. So
the *intrinsic complexity* of gcd and of coprimeness, which bounds the cost of every
uniform process from below, is o(log a). This refutes Conjecture 3.4 and (4F-5). With the
book's Theorem 4F.1, a single uniform process attains this cost, ruling out the
possibility raised on p. 188 of the book that the Main Conjecture holds for all uniform
processes. It also means the homomorphism method, the standard tool for such lower
bounds, cannot prove a logarithmic one. The terms are defined under
[Notation](#notation).

**Still open: the Main Conjecture for algorithms.** A derivation chooses which values to
combine for free, so it does not give a program with this cost, and no single program with
o(log a) remainder calls is known.

**Also proved.** For remainder-only derivations, the known Ω(log log a) lower bound,
previously proved for specific hard pairs, holds for almost all coprime pairs. For each
ε > 0 there is a fixed nondeterministic gcd program, using a fixed number of registers and
no recursion, whose cost is at most ε log₂ a + Bε; the program depends on ε. The bound
also settles van den Dries and Moschovakis's open problem on the closure depth of the gcd
(2009).

**Verified.** Everything above is machine-checked in Lean 4, except the step that uses the
cited Theorem 4F.1; the refutations of Conjecture 3.4 and (4F-5) do not need it. This
includes the link to the book's own definitions: Lean states the book's certificates and
intrinsic complexities directly and proves them equal to those used in the refutations.
The result has not yet been reviewed by an expert in the area.

## Results

### Notation

- A *derivation* from a, b lists a, b and then values rem(x, y) of two earlier entries
  with y > 0; earlier values are kept and no numerical constants are introduced. G(a, b)
  is the least number of remainder calls in a derivation of gcd(a, b). D(a, b), for
  coprime a, b, is the length of a shortest derivation of 1; it equals G(a, b) there, and
  is used in the Lean names.
- Nε = (ℕ, rem, eq0, eq1) is the Euclidean structure, where eq0 and eq1 are the tests
  x = 0 and x = 1, and ⊥⊥ is the coprimeness relation (x, y ≥ 1 and gcd(x, y) = 1).
- A *certificate* for a relation or function f at inputs a, b is a finite partial
  substructure generated by a, b on which every homomorphism into the structure respects
  f at (a, b) (the Homomorphism Test). The *intrinsic calls(rem)-complexity*
  calls(rem)(Nε, f, a, b) is the least number of remainder facts in a certificate; a
  remainder fact corresponds to a remainder call.
- The ε in Nε is the book's name for the Euclidean structure, not the small ε > 0 in
  the bounds. The book also writes ε for the Euclidean algorithm; like the paper, we
  write Eucl.
- Bε is a constant depending only on ε.
- log means log₂; the base is irrelevant inside O and o.

### Upper bound and refutations

The refined upper bound is **(3 + o(1)) log₂ a / log₂ log₂ a**, uniformly in b.
Precisely, for every ε > 0, the coefficient 3 + ε works for all sufficiently large a
and every 0 ≤ b ≤ a. The same leading coefficient holds for the intrinsic
remainder-call complexities below on positive inputs. No optimality of 3 is claimed.
The coefficient rests on the sharper form of the Euclidean-prefix lemma: modulo every
m > 2a/r_h, each residue class contains at most three of the prefix values r_0, …, r_h.

As a consequence, the intrinsic calls(rem)-complexity of both coprimeness and gcd in
Nε is o(log a), uniformly over pairs with 1 ≤ b ≤ a. This refutes the uniform-process
form of van den Dries and Moschovakis's conjecture that the Euclidean algorithm is
optimal among its peers:

- **Conjecture 3.4** of Moschovakis's 2012 notes, *Absolute lower bounds for uniform
  processes*. We prove there is no real r > 0 with calls(rem)(Nε, ⊥⊥, a, b) ≥ r log a
  for infinitely many pairs a ≥ b ≥ 1. The notes' exact wording (rational r, infinitely
  many values of a) is refuted too.
- **The "precise version" (4F-5) of the Main Conjecture** in Y. N. Moschovakis,
  *Abstract Recursion and Intrinsic Complexity*, Lecture Notes in Logic 48, Cambridge
  University Press / ASL, 2019, doi:10.1017/9781108234238 (p. 151; all page citations
  refer to this published edition). It asks for a set D ⊆ ℕ² and a K > 0 such that

  $$(x, y) \in D \implies \mathrm{calls}_{\mathrm{rem}}(\mathrm{Eucl}, x, y) \le L(x, y) \le K \cdot \mathrm{calls}_{\mathrm{rem}}(\mathcal{A}, \gcd, x, y),$$

  where L(x, y) = 2 log max(x, y), with L(0, 0) = 0, and Eucl is the Euclidean
  algorithm. We prove that for every K > 0 the second inequality holds on only finitely
  many pairs, both for gcd certificates without eq1 facts (𝒜 = (ℕ, rem, eq0)) and for
  certificates in Nε. The book's form, with a set D on which the complexity is unbounded
  (condition (4F-4)), is refuted as well. These statements omit the first inequality,
  which only weakens the statement being refuted.
- **The possibility raised after Corollary 6C.7 (p. 188)**, that the Main Conjecture
  "holds for all uniform processes of Nε". Ruling this out also uses the book's
  best-uniform-process theorem (4F.1), which turns a small intrinsic complexity into a
  uniform process with that complexity. Theorem 4F.1 is cited, not formalised.

### Further results

- **Almost-all lower bound.** For every ε > 0, among coprime pairs b < a ≤ N, all but
  o(N²) have D(a, b) > (1 − ε) log₂ log₂ N. So, for remainder-only derivations, the known
  Ω(log log a) lower bound, previously proved for specific hard pairs, holds for almost
  all coprime pairs.
- **Program family.** For every ε > 0 there is a fixed nondeterministic gcd program,
  using only rem and eq0, with a fixed number of registers and no recursion, whose cost
  is at most ε log₂ a + Bε on all positive inputs a ≥ b. Written one function per line, it
  is also a tail-recursive program in the book's sense. See
  [Program family](#program-family).
- **The homomorphism-test barrier.** The Homomorphism Test applied to all generated
  primitive operation diagrams cannot prove a logarithmic lower bound: every input has a
  certificate with o(log a) remainder facts. This leaves open arguments combining
  homomorphisms with additional restrictions on computations.
- **Closure depth.** The bound settles the Open Problem at the end of §3 of van den Dries
  and Moschovakis, *Arithmetic Complexity*, ACM Transactions on Computational Logic 10(1),
  2009, doi:10.1145/1459010.1459012 (p. 2:11;
  [preprint](https://www.math.ucla.edu/~ynm/papers/ac.pdf)). There g(a, b) is the least
  number of parallel stages, starting from {0, 1, a, b} and applying +, −, integer
  quotient and remainder to all available pairs, after which gcd(a, b) is available. They
  ask whether g(aₙ, bₙ) > C log aₙ along some sequence with aₙ → ∞. Since rem(b, a)
  appears at the first stage, g(a, b) ≤ 1 + G(a, rem(b, a)) = O(log a / log log a)
  uniformly in b, so no such sequence exists. This is formalised with the source's
  definitions of iq, rem and the stages, including their conventions at zero divisors.

### What remains open

**The Main Conjecture for algorithms.** The result shows that a proof of it must use
properties beyond uniformity. It stays open because the construction gives no
remainder-only algorithm, deterministic or nondeterministic, with this cost: choosing
which two stored residues to combine is not charged, and a program would still need to
implement reusable access to the growing stored prefix within the claimed cost. The
[program family](#program-family) shows that the obstacle is memory, not recursion:
W registers give coefficient about 6 / log₂ W (about 3 / log₂ W with the paper's
three-per-class count, not formalised). Whether every W-register program needs
c log a / log W calls is open. (Pratt's algorithm, as presented in the book, is also a
nondeterministic register program; we did not obtain his unpublished manuscript.)

## Program family

For each p ≥ 1, a nondeterministic register program over (ℕ, rem, eq0) with 4ᵖ + 7
registers (the two inputs and 4ᵖ + 5 work registers) and no stack has worst-case cost at most
(3/p + o(1)) log₂ a, uniformly in b ≤ a (paper, §7). Cost is the minimum number of
remainder calls over convergent computations; every convergent computation returns the
gcd, and every input has one. **This does not give one sublogarithmic program**: the
program depends on p, and the Main Conjecture allows its lower-bound coefficient to
depend on the program.

The construction keeps a fixed-length Euclidean prefix and the contractions. Once the
modulus m is small, it computes a mod m and b mod m and finishes with two Euclidean
loops in place. The size thresholds appear only in the proof; the program does not
compute them.

Lean checks the result for formal versions of two of the book's models of computation.

- **Register programs** (§2F, with the nondeterminism of §2E): `Register.Program` is
  the book's syntax for programs over (ℕ, rem, eq0): numbered lines of assignments
  u_i := t, branchings on a test and halts, with the book's prime terms (u_i,
  rem(u_i, u_j), tt, ff, eq0(u_i)), several alternative commands per line, and the
  book's iterator semantics. `TailSource.program` is the gcd program in this syntax. The
  main line never writes the inputs u₀, u₁; the final verification sets
  u₀ := rem(u₀, u_i) and u₁ := rem(u₁, u_i) and tests both for zero. The generator used
  in the cost proofs (`TailProgram.Run`) can also relabel all registers at once for
  free; `TailSource.run_trace_relabel` removes this, replaying a relabelled run on the
  physical registers with the same remainder calls and no extra registers.
- **Recursive programs** (§§2A, 2E): `Register.compile` translates every register
  program into a recursive program one function per line, as in the book's reduction
  of iteration to tail recursion (§2C). Each line becomes a function of the k
  registers: an assignment becomes a tail call with one argument replaced, a branching
  on eq0(u_i) a zero-test conditional between two tail calls and one on tt or ff a
  single tail call, a halt its term, and alternative
  commands alternative bodies. For every register program, `Register.eval_iff_halts`
  matches evaluations exactly, in value and remainder cost, with convergent
  computations; `Register.compile_tailRecursive` proves that every call is in tail
  position; and `Register.stacks_bounded` that on the machine the control and value
  stacks never hold more than 2k + 4 entries, on any input and however long the
  computation runs. `TailRecursive` applies this to the gcd program, with k = 4ᵖ + 7
  registers, so its stacks never exceed 2·4ᵖ + 18 entries.

The result concerns the minimum successful cost of nondeterministic programs. It does
not settle the book's Problem x2G.6, which asks whether every recursive function in
the pointed Euclidean structure is tail recursive.

<details>
<summary>Model conventions</summary>

Remainder evaluation requires a positive divisor, so Lean's total `Nat.mod` at zero is
never used as a successful primitive call. Incorrect candidates loop; divergent or stuck
computations do not count as successful. The result requires one successful computation
on every input and correctness of every terminating one, without fairness or
termination of all branches. Cost counts only remainder calls, including the two final
verification calls, not machine steps or the work of finding successful choices.
Positive scaling preserves successful runs and their costs (`TailProgram.Run.scale`).

The language of `Recursive` has terms with variables, remainder, a zero-test conditional
and calls of internal symbols, each with a set of alternative bodies (finitely many for the
gcd program, `TailRecursive.bodies_finite`), evaluated call by value.
For every such program, `Recursive.Machine.eval_iff_steps` proves exact-cost equivalence
with a specialisation of the book's two-stack machine (Table 1, p. 75): arguments are
evaluated right to left, zero tests and branches are separate transitions, and only
remainder transitions are charged. Machine closures implement substitution; programs
cannot inspect them as data; for the gcd program each closure environment has at most w + 2
entries.

## Finite checks

[scripts/check.sh](scripts/check.sh) builds the library, reruns the axiom audit and the
quick finite checks below, and compares each output with its recorded file; CI
([.github/workflows/ci.yml](.github/workflows/ci.yml)) runs it on every push and pull
request. It leaves out `check_prefix_lemma.py`, which takes about a minute and checks a
lemma that Lean proves in general. A separate manual workflow
([palomar-preflight.yml](.github/workflows/palomar-preflight.yml)) runs Palomar's own
verifier, including the comparator, on a chosen commit.

```sh
python3 scripts/check_certificates.py
python3 scripts/benchmark_certificates.py
python3 remainder_only_certificate.py
python3 scripts/check_prefix_lemma.py
```

- **[check_certificates.py](scripts/check_certificates.py)** runs a 310-case suite. It
  covers zero inputs, equal inputs, scaled non-coprime inputs, random large inputs and
  Fibonacci pairs. With seed 20261016 and base size 64 bits, the 310 cases include
  175 noncoprime pairs and exercise 3,543 contractions. Four invalid traces are rejected.
- **[benchmark_certificates.py](scripts/benchmark_certificates.py)** reproduces the
  manuscript's table (about 15 seconds). With seed 20261016 and base size 256 bits, it
  samples 25 coprime pairs at each of 512, 2048 and 8192 bits (a uniform of that bit
  length, then b uniform in [2, a − 1] until coprime) and adds the first Fibonacci pair
  of each size: (F_k, F_{k−1}) with k = 738, 2951 and 11801, respectively.
  Every derivation is replayed, and the worked contraction from (44, 17) is
  checked. The Euclidean count stops when the gcd first appears. Results, with input
  hashes and individual counts, are in
  [validation/benchmark_certificates.json](validation/benchmark_certificates.json).
- **[remainder_only_certificate.py](remainder_only_certificate.py)** contains the planner
  and replay checker. Run directly, it prints one example per size, using seed 20261016
  and base size 256 bits.
- **[check_prefix_lemma.py](scripts/check_prefix_lemma.py)** checks the Euclidean-prefix
  lemma (`prefix_pairs_distinct`): if r_0 = a, r_1 = b, r_2, … are the Euclidean
  remainders and m > 2a/r_h, then the pairs (r_i mod m, r_{i+1} mod m), 0 ≤ i < h, are
  distinct. It checks every coprime pair with 3 ≤ a < 1500 and 1 ≤ b < a, every prefix
  length h, and up to 60 consecutive moduli above the threshold 2a/r_h, restricted to
  m < 4a. This gives 254,722,179 instances. A failure exits with a nonzero status and
  reports the first counterexample. As a control it also counts collisions when the
  threshold is dropped.

Results are in [validation/](validation/). The scripts search for derivations with
ordinary arithmetic; only the remainder facts of the derivation they return are counted.
These finite checks supplement the Lean proof.
